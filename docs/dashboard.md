# Dashboard

The dashboard is a set of server-rendered pages behind the dashboard password. Every owner action is a plain form that posts and returns to the page, so the dashboard needs no JavaScript.

| Page        | What it shows                                                                                                                                       | What you can do there                                                                                                                                                             |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Overview    | What needs you, work in progress with its running threads and why a card waits, and finished work with merged, reverted, and abandoned counts       | Approve a merge at the head commit shown, send a card to the lead, abandon a card, admit or reject an issue, dismiss a notification, open a proposal, pause or resume the factory |
| Work items  | Cards and tracked issues, filtered by project and stage; each card's PR, worker, escalation, threads, and timeline; each thread's recorded activity | The same card and issue actions                                                                                                                                                   |
| Pipeline    | Cards in each stage by role, with their running threads, the thread count against the limits, and why no thread may start                           |                                                                                                                                                                                   |
| Activity    | Card events, the planner's, lead's, and improver's MCP calls, and notifications, newest first                                                       | Filter by kind and by role                                                                                                                                                        |
| Analytics   | PRs, merges, reverts, abandoned cards, escalations, and cycle time per UTC day, for one project or all, as charts with a table under each           | Pick the project and the period                                                                                                                                                   |
| Improvement | Each improver proposal with its diff and evidence threads, and past proposals                                                                       | Approve a proposal, which deploys it, or reject it                                                                                                                                |
| Workers     | Linked T3 environments and worker setup                                                                                                             | Use as a worker, deploy, sign in Claude and Codex, check sign-in, set the config repo                                                                                             |
| Settings    | Config versions and their diffs                                                                                                                     | Edit, approve, reject, revert, and deploy                                                                                                                                         |

"Needs you" on Overview counts cards escalated to you, issues waiting for admission (including issues held by a project's cap), improver proposals, T3 links that expire within 7 days, workers whose next step is yours, and notifications you have not dismissed.

A page that cannot read Hephaestus's store shows an error banner and leaves out the actions that depend on the missing data. When T3 or GitHub fails, the page shows a short reason, such as an error code, and the service log has the full error. When T3 has not answered within 2 seconds, the parts of the page that need T3 show as loading, and the page reloads every 5 seconds until T3 answers.
