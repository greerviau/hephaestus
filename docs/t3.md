# T3 integration

Hephaestus drives this host's T3 server, and through it the linked worker environments, with T3's outside MCP server over loopback. It reads T3's port from `~/.t3/userdata/server-runtime.json` (or under `T3CODE_HOME`).

- Install records the absolute path of the `t3` CLI, because the systemd user manager's `PATH` is usually shorter than a login shell's. On first use, the service runs `t3 auth pairing create` for a 5-minute pairing code and signs itself in with it. No browser is needed. It keeps the 30-day token in `~/.hephaestus/secrets.json`, and signs in again 3 days before the token expires or when T3 rejects it, revoking its earlier session.
- It records every factory thread with its task, worker, provider instance, model, and config version, and copies each thread's activity into `state.db` while the thread runs. T3 updates items in place, so Hephaestus re-reads from the oldest item that is not final, and fetches the rest of any text T3 cut short. Restarts lose and duplicate nothing. Each thread is polled on its own and backs off up to 5 minutes after errors. A thread T3 no longer has is marked unavailable, and its history stays.
- It settles each thread it started once the thread has ended and no active task uses it: a deploy, sign-in, check, or cleanup thread as soon as it ends, and a task's implement and review threads when the task is done or abandoned, or when a newer thread replaces them. An escalated task keeps its threads. Settling only moves a thread out of T3's active list; its history stays readable.
- T3 cannot send attachments to a linked environment, so content for a worker goes inline in the thread's first message.
- The Workers page lists the linked environments with reachability, access, and link expiry, and Home warns 7 days before a link expires.
- Uninstall revokes the T3 sessions Hephaestus signed in.

See [Development](development.md#integration-tests) for the integration test against a real worker.
